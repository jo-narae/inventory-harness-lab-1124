영역마다 원본은 하나다. 문서끼리 내용이 어긋나면 [3. 충돌 정책](#3-충돌-정책)을 따른다.

## 2. 영역별 범위

### 재고 도메인 — `docs/01-requirements.md`

재고를 세는 단위, 기능 요구, 데이터 모델(개념), 비기능 요구, 범위 제외, 완료 기준, 확인이 필요한 가정.

- 업무 규칙(FEFO/LEFO, 사유 체계, 정산 역산 등)이 무엇인지에 대한 판단은 여기서 한다.
- 완료 기준(§7)은 도메인 차원의 수용 기준이다. 검증 규칙이 생기기 전까지는 이것이 "다 됐는가"의 기준이다.

### 아키텍처 — `docs/06-architecture.md`

스택, 폴더 구조, 데이터 모델(`prisma/schema.prisma`와의 대응), 핵심 로직, 상태 흐름, 인증, 시드 설계, 결정 요약(§7.5), 동시성·성능.

- 코드와 이 문서가 다르면 둘 중 하나가 틀린 것이다. 의도된 변경이면 이 문서를 먼저 고친다.
- §9 "자동 테스트로 지킬 불변식"은 검증 규칙이 생기면 그쪽으로 옮긴다.

### 개별 작업 — GitHub Issue

작업 하나의 목적, 범위, 완료 조건은 그 작업의 Issue가 원본이다.

- 작업 중에 범위가 바뀌면 Issue를 고친다. 대화나 커밋 메시지에만 남기지 않는다.
- Issue가 다른 원본과 충돌하면 [3. 충돌 정책](#3-충돌-정책)을 따른다.

### 검증 규칙 — `docs/harness/VerifyRule.md`

통과 기준(`npm run verify` exit 0), 검증 단계와 순서, 검증 환경, Architecture Check, 실행 위치(로컬·CI), 판정과 보고, 검증 규칙을 바꾸는 방법.

- 변경사항이 "통과했다"고 말할 수 있는지에 대한 판단은 여기서 한다.

### 루프 규칙 — `docs/harness/Loop.md`

Issue 작업을 시작해서 로컬 검증(`npm run verify`)을 통과하거나 멈출 때까지의 절차. 시작 점검, 시도 기준과 상한, Issue 코멘트로 남기는 루프 기록, `NEEDS_HUMAN` 선언 · 사람의 응답 · 재개, 세션이 바뀌었을 때 복구.

- 통과 기준 자체는 검증 규칙(`VerifyRule.md`)이 정한다. 이 문서는 그 기준을 몇 번까지, 어떻게 기록하며 돌리는지만 정한다.
- 커밋 · 푸시 · PR · CI, 브랜치 전략, Issue 닫기, 판정 테스트의 승인 · 보호는 아직 이 문서 범위 밖이다.

## 3. 충돌 정책

여기서 **SSOT**는 1절 원본 목록에 있는 문서(도메인·아키텍처 원본)를, **참고 문서**는 그 밖의 모든 문서를 말한다.

| 충돌 | 처리 |
|---|---|
| 참고 문서 ↔ SSOT | **SSOT를 우선한다** |
| Issue ↔ SSOT | **`NEEDS_HUMAN`** 상태를 선언하고 사람에게 판단을 요청한다 |
| SSOT ↔ SSOT | **`NEEDS_HUMAN`** 상태를 선언하고 사람에게 판단을 요청한다 |

**AI는 충돌이 발생하면 자신의 판단대로 행동하지 않는다.**

---

## 4. 보호 영역과 소유권

영역마다 읽기 권한과 변경 권한을 나눈다.

| 영역 | 대상 | AI | 사람 |
|---|---|---|---|
| 애플리케이션 코드 | `src/`, `prisma/`, `scripts/` (검증 스크립트 제외) | Issue 범위 안에서 수정 | 최종 승인 |
| Issue별 테스트 | `tests/` | 작성 · 수정 | 전제 검토 |
| 요구사항 · 아키텍처 | `docs/01-requirements.md`, `docs/06-architecture.md` | 읽기 | 변경 · 승인 |
| 하네스 핵심 규칙 | `docs/harness/`, `AGENTS.md`, `CLAUDE.md` | 읽기 | 변경 · 승인 |
| 검증 스크립트 | [`VerifyRule.md`](VerifyRule.md) 7절의 대상 파일 | 실행 | 정책 변경 승인 |

AI에게 "읽기"만 허용된 영역을 바꿔야 한다고 판단되면, 직접 고치지 않고 사람에게 변경을 요청한다.

단, 사람이 이 영역의 수정을 직접 요청하면 AI는 그 요청대로 수정한다. 수정 범위는 요청받은 내용으로 한정한다.
